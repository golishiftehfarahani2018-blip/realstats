# تحویل نسخه اول سامانه دفتر املاک

این نسخه، گردش کاری یک دفتر را از ثبت ملک و مشتری تا همکاری، ویترین، معامله و ثبت دستی تسویه پوشش می‌دهد. داده‌های نصب ابری کاملاً ساختگی‌اند. هیچ اتصال بانک، پیامک، درگاه پرداخت، انتشار اینترنتی یا تأیید حقوقی خودکار وجود ندارد.

## قابلیت‌های ساخته‌شده

- کارکنان: ورود نشست‌محور، CSRF، ابطال نشست مشاور غیرفعال، مدیریت مشاور و دعوت ۲۴ساعته یک‌بارمصرف. دعوت نقش مدیر ایجاد نمی‌کند و فقط هش آن ذخیره می‌شود؛ لینک با fragment در مرورگر منتقل می‌شود.
- املاک: پیش‌نویس، بررسی مستقل، بانک مشترک با صفحه‌بندی/فیلتر، جزئیات اعلامی بنا و زمین، مقدار نامعلوم مستقل از خیر، قیمت توافقی صریح، تاریخچه قیمت و مدارک تصویری خصوصی. قیمت توافقی، تطبیق قطعی بودجه محسوب نمی‌شود.
- بازنگری: پیشنهاد اصلاح عرضه تأییدشده، نسخه مبنا، منع خودتأییدی، حفظ محتوای پیشنهاد و ثبت تصمیم. تأیید بازنگری، انتشار قبلی را متوقف می‌کند؛ انتشار دوباره نیازمند بازبینی مدیر است. تغییر مشخصات یک ملک مشترک چند عرضه، برای جلوگیری از تغییر بی‌سابقه سایر عرضه‌ها مسدود است؛ قیمت همان عرضه مستقل بازنگری می‌شود.
- مشتری داخلی: روابط مالک/متقاضی، شاخص HMAC تلفن، هشدار تکرار بدون افشای هویت، تقاضا و تطبیق توضیح‌پذیر، همکاری، ارجاع مستقل، بازدید، پیگیری خصوصی و اعلان گیرنده‌محور.
- ویترین: snapshot فهرست‌سفید، رضایت مستند، بازبینی مدیر، توقف/لغو فوری، فیلتر و صفحه‌بندی، لینک جزئیات و تصاویر عمومی جدا از مدارک. هر تصویر عمومی JPEG/PNG واقعی بازکدگذاری و EXIF حذف می‌شود؛ مدیر باید نبود تماس/مدرک/نشانی روی خود تصویر را دستی تأیید کند. تشخیص خودکار متن حساس یا OCR ادعا نمی‌شود. bucket عمومی نیز دانلود بی‌مجوز مستقیم ندارد؛ API فقط تصویر آگهی فعال را تحویل می‌دهد.
- حساب مشتری: نام کاربری و رمز، کنترل CSRF و تلاش ورود، علاقه‌مندی، درخواست بازدید/اطلاعات و پیگیری درخواست‌های شخصی. پس از توقف آگهی نیز ورود مشتری و سوابق خودش باقی می‌ماند. این حساب از عضویت کارکنان جداست؛ تماس/نشانی مالک را دریافت نمی‌کند. متن درخواست فقط برای مدیر و معرف عرضه است. تأیید شماره تلفن/OTP فعال نیست.
- مالی: معامله، توافق صریح مدیر و نسخه اصلاحی، سهم ثابت یا درصدی با دقت دو رقم اعشار، سهم دفتر صریح، ثبت نقش‌های متعدد یک ذی‌نفع، تقسیم باقیمانده پایدار با عدد صحیح، وصول ناخالص و بخش قابل تقسیم مستقل، آزادسازی تجمعی سهم متناسب با وصول، موافقت/اعتراض و تعیین تکلیف مدیر، پرداخت محدود به مانده، عملیات یکتا و سند معکوس. لغو، سابقه دریافت/پرداخت را حذف نمی‌کند؛ سند معکوس پس از لغو نیز قابل ثبت است. برگشت وصول می‌تواند مانده قابل بازپس‌گیری ایجاد کند. ذی‌نفع تاریخی از توافق جدید حذف نمی‌شود؛ سهم صفر ممکن است. هیچ تعرفه، درصد نمونه، مالیات یا کسر قانونی به‌صورت پیش‌فرض فعال نشده است.
- مدیریت و عملیات: نام/شهر/رنگ دفتر با نسخه، گزارش دفتر و CSV بدون تماس، ممیزی غیرقابل بازنویسی، یادآور داخلی وظایف سررسیدگذشته و ارجاع درخواست همکاری بی‌پاسخ به مدیر. worker هر ۶۰ ثانیه بررسی می‌کند و هر رویداد برای هر رکورد/گیرنده یک بار ارسال می‌شود. مهلت همکاری با تنظیم صفر غیرفعال است؛ مقدار مثبت به ساعت تقویمی است و عنوان «ساعت کاری» ندارد.

## اجرای نصب تازه

از ریشه پروژه و روی محیط آزمایشی دارای Docker/Compose v2:

```bash
python3 infra/init_env.py
docker compose up --build -d
docker compose logs migrate storage-init worker
docker compose run --rm backend python manage.py seed_demo
docker compose run --rm backend python manage.py seed_crm_demo
docker compose run --rm -e RUN_STORAGE_TESTS=1 backend python manage.py test core crm business --noinput
```

seed فقط برای نصب خالی آزمایشی است. برای نصب مشتری، bootstrap_office در runbook جایگزین seed است. رمزهای تصادفی seed را عمومی نکنید. .env و کلید رمزنگاری را حفظ کنید و داخل سورس/بسته تحویل نگذارید. تولید دوباره کلید برای بانک موجود، داده رمزنگاری‌شده و شاخص تلفن را خراب می‌کند.

در محیط ابری این گفتگو، CA شبکه و bypass پراکسی سرویس‌های داخلی در `/workspace/realstats-cloud` ثبت شده‌اند. راه‌اندازی همان نصب:

```bash
docker compose -f compose.yaml -f /workspace/realstats-cloud/compose.cloud.yaml up --no-build -d
```

پس از آماده‌شدن backend و frontend و در صورت تغییر IP کانتینرها، nginx را restart کنید. موفقیت migrate و storage-init و پاسخ واقعی درخواست‌ها را بررسی کنید. worker باید در حال اجرا باشد. TLS محلی آزمایشی در override جداست و گواهی آن کوتاه‌عمر است؛ جایگزین دامنه و گواهی استقرار نیست.

## نتیجه پذیرش در این محیط

- ۸۸ آزمون با PostgreSQL و S3 واقعی؛ شامل رقابت دو اتصال واقعی برای ثبت مالی با یک نسخه: یک ثبت و یک تعارض.
- Django check، نبود drift مدل/migration، اعتبارسنجی OpenAPI، TypeScript و build واقعی Next.js و Docker.
- مرورگر واقعی: رضایت/انتشار، مشتری موبایل/ثبت‌نام/علاقه‌مندی/درخواست، صندوق دفتر/تغییر وضعیت، معامله/توافق/وصول/پرداخت/برگشت/لغو، گزارش، موافقت مشاور با سهم شخصی، دعوت و ورود مشاور فاقد مجوز مدیریتی.
- HTTPS محلی با DEBUG=0، بررسی واقعی گواهی و hostname با CA مورد اعتماد صریح، کوکی Secure/HttpOnly، CSRF، HSTS و خروج.
- بازیابی همه ۴۰ مدل ثبت‌شده در بانک جدا و مقایسه همه ردیف‌ها/مقادیر رمزگشایی‌شده؛ کپی دو bucket و تطبیق checksum رسانه آزمایشی و اتصال مدرک بازیابی‌شده به رسانه بازیابی‌شده. بانک و bucket اصلی بازنویسی نشدند.
- بررسی بار کوچک محلی: ۱۰۰ درخواست ویترین با هم‌زمانی ۵؛ تمام پاسخ‌ها معتبر. ارقام تأخیر در evidence/release/local-load.txt؛ این اندازه‌گیری ظرفیت عملیاتی سرور آینده را اثبات نمی‌کند.

گزارش‌ها در `docs/evidence/release` هستند. برای مشاهده محصول در این نصب، مسیر داخلی کارکنان `/`، ویترین `/showcase` و پذیرش دعوت `/join` است. محیط onboarding لینک عمومی تعاملی ارائه نمی‌کند؛ گزارش تصویری، فیلم مرور تصاویر واقعی و بسته سورس جدا تحویل داده می‌شوند.

## حدود نسخه و پیش‌نیاز بهره‌برداری

این پایان قابلیت‌های اصلی نسخه اول تک‌دفتره است؛ فروش اشتراک، خرید آپدیت، چندشعبه عملیاتی، اپ بومی، حسابداری کل، قرارداد/ثبت رسمی و اتصال پلتفرم‌های آگهی جزء دامنه نسخه اول نبودند. اصلاح/ادغام هویت اشخاص، تقویم ورودی شمسی اختصاصی، ارتقای تطبیق بیش از سقف ۱۰۰۰ عرضه و SLA ساعت کاری توسعه‌های بعدی‌اند و جای آن‌ها دکمه نمایشی ساخته نشده است.

پیش از استفاده واقعی: سرور/دامنه و TLS معتبر، ذخیره امن و زمان‌بندی backup، آزمون بازیابی همان محیط، سیاست نگهداری داده، قواعد واقعی کارمزد/کسورات و ساعات پاسخ دفتر تعیین شوند. اگر تأیید تلفن/پیامک لازم است، سرویس و اعتبارنامه‌اش باید از تنظیمات امن تأمین شود؛ در این نسخه ورود مشتری با رمز است. هیچ داده واقعی، مبلغ بانکی یا پیام بیرونی در آزمون‌ها استفاده نشده است.
