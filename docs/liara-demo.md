# نسخه نمایشی مستقل در لیارا

هیچ برنامه، دیتابیس، دامنه، DNS، باکت یا کلید سایت قبلی نباید تغییر کند. این بسته فقط برای یک **برنامه Docker تازه** به همراه PostgreSQL تازه و دو باکت تازه آماده شده است. موجودی و هزینه سرویس‌ها هنوز در حساب بررسی نشده‌اند؛ هیچ منبع پولی از این محیط ساخته نشده است.

## معماری پیشنهادی دمو

- یک برنامه Docker جدید با شناسه یکتا مانند realstats-demo-…؛ پنل، ویترین، Nginx و یادآور داخلی در همان کانتینر و تنها یک پورت HTTP یعنی 8080 اجرا می‌شوند.
- یک PostgreSQL مستقل در همان شبکه خصوصی؛ از دیتابیس سایت قبلی استفاده نشود.
- دو باکت مستقل برای مدارک خصوصی و تصاویر عمومی بازبینی‌شده؛ دسترسی مستقیم ناشناس به هر دو بسته باشد. تصاویر ویترین از API مجاز سرو می‌شوند.
- آدرس پیش‌فرض تازه‌ای که لیارا برای برنامه می‌دهد؛ دامنه یا تنظیمات سایت قبلی دست‌نخورده بماند. TLS در لبه لیارا خاتمه می‌یابد و برنامه فقط به proxy مورد اعتماد متکی است.
- نقطه شروع منابع برای بررسی پلن: برنامه حدود ۱ گیگابایت RAM و PostgreSQL کوچک مستقل؛ این اندازه توصیه اولیه دمو است، نه قیمت قطعی یا تضمین ظرفیت. پلن و هزینه نهایی باید در پنل تأیید شوند.

لیارا Docker Compose معمولی را مستقیماً اجرا نمی‌کند. فایل liara.json ریشه، مسیر infra/liara/Dockerfile و پورت 8080 را تعریف می‌کند. ساخت برنامه جدید را با Docker انتخاب کنید و فقط مخزن realstats را به همان برنامه تازه متصل کنید. نوع استقرار در آغاز دستی باشد. اتصال GitHub یا تنظیمات برنامه سایت قبلی تغییر نکند.

## متغیرها فقط در تنظیمات امن برنامه جدید

ESTATE_INSTALLATION_ID به صورت UUID تازه و ثابت مختص این دمو؛ DEBUG=0، DJANGO_SECRET_KEY و FIELD_ENCRYPTION_KEY با مقادیر تازه مختص همین دمو؛ POSTGRES_DB، POSTGRES_USER، POSTGRES_PASSWORD، POSTGRES_HOST و در صورت نیاز POSTGRES_PORT از دیتابیس جدید؛ ALLOWED_HOSTS فقط hostname برنامه جدید و CSRF_TRUSTED_ORIGINS آدرس کامل https همان برنامه؛ S3_ENDPOINT به‌صورت https، S3_ACCESS_KEY و S3_SECRET_KEY مربوط به باکت‌های جدید، S3_PRIVATE_BUCKET و S3_PUBLIC_BUCKET با نام دو باکت جدید.

کلیدهای محیط مجازی یا سایت قبلی را به دمو کپی نکنید و متغیرها را در GitHub ننویسید. فایل .dockerignore ریشه، env، کلیدها، dumpها و خروجی‌های محلی را از build حذف می‌کند. پس از ساخت دمو، کلید FIELD_ENCRYPTION_KEY آن باید برای تمام ارتقاها حفظ شود.

راه‌انداز migration و init_storage را روی **همان منابع جدید تعریف‌شده** اجرا می‌کند؛ seed خودکار و رمز ثابت وجود ندارد. برای مدیر دمو، bootstrap_office از ترمینال برنامه جدید اجرا شود؛ یا فقط روی دیتابیس آزمایشی خالی seed_demo و seed_crm_demo استفاده شوند. رمز حساب‌ها فقط در ترمینال خصوصی نمایش داده می‌شود.

## دسترسی لازم برای انجام استقرار توسط عامل

در این جلسه اتصال حساب لیارا وجود ندارد. برای API می‌توان یک کلید کوتاه‌عمر در بخش API پنل ساخت و فقط در تنظیمات امن همین محیط با نام LIARA_API_TOKEN وارد کرد؛ هرگز در چت یا مخزن نفرستید. این کلید برای API رسمی api.liara.ir تعریف شده است. قبل از ساخت منابع، فهرست پلن‌ها و مبلغ در حساب بررسی و هزینه با مالک تأیید شود. برای تیم، Team ID نیز لازم است.

## بررسی بعد از استقرار

/healthz باید پاسخ 200 واقعی با اتصال بانک بدهد. سپس ورود مدیر روی HTTPS، Secure/HttpOnly، CSRF، ویترین، حساب مشتری، درخواست آزمایشی و بارگذاری/دانلود و لغو انتشار رسانه بررسی شوند. لاگ startup نباید env یا رمزها را چاپ کند. نبود منابع/متغیر لازم باید استقرار را ناموفق کند و نباید به سایت قبلی fallback شود. نمونه‌های قبلی داده واقعی یا تعرفه قانونی نیستند.

راه‌انداز پیش از migration، بانک را بررسی می‌کند: بانک غیرخالی بدون نشانگر این نصب، یا دارای شناسه نصب متفاوت را رد می‌کند. برای بانک تازه، نشانگر اختصاصی ساخته می‌شود؛ ESTATE_INSTALLATION_ID باید در تمام ارتقاها ثابت بماند. این کنترل، جایگزین بررسی شناسه سرویس جدید در پنل نیست.

## نتیجه آزمون بسته

ساخت واقعی image موفق بود. در آزمون محلی با محدودیت ۱ GiB RAM و یک CPU، PostgreSQL مستقل و ذخیره‌ساز HTTPS با گواهیِ مورد اعتماد صریح استفاده شد؛ migration، پنل، ویترین، CSRF و /healthz پاسخ موفق داشتند. راه‌اندازی تکراری با نشانگر ثابت و خروج تمیز SIGTERM آزموده شد. اشاره عمدی به یک بانک قدیمیِ فاقد نشانگر، پیش از migration رد شد و تاریخچه آن تغییر نکرد. گزارش در evidence/liara/container-smoke.txt است. این آزمون محلی است و موفقیت استقرار واقعی لیارا تا زمان دسترسی و اجرای آن ادعا نمی‌شود.
