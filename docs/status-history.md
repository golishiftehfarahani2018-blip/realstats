# تکمیل بانک املاک: فیلتر ترکیبی و صفحه‌بندی

رابط بانک مشترک، پرونده‌های در دسترس و صف بررسی اکنون از صفحه‌بندی سرور با ۳۰ نتیجه در هر صفحه استفاده می‌کنند. شمارش و انتخاب صفحه پس از اعمال مجوز دفتر/رکورد، وضعیت بخش و فیلترها انجام می‌شود. ترتیب ثابت created_at و id است؛ این روش offset در زمان تغییر هم‌زمان رکوردها snapshot ایجاد نمی‌کند.

فیلترهای نوع ملک، معامله، محله، حداقل/حداکثر متراژ و قیمت فروش یا ودیعه/اجاره مستقل اضافه شدند. مبالغ صحیح تومان‌اند؛ ارقام فارسی پذیرفته می‌شوند. بازه معکوس، مقدار نامعتبر، فیلد ناشناخته و فیلتر قیمت بدون تعیین نوع معامله رد می‌شوند. تماس و نشانی خصوصی وارد فیلترها یا نتایج نمی‌شوند.

API: GET /api/v1/offerings?paginated=1&limit=30&offset=0. پاسخ count، offset، limit، has_more و results است. حد مجاز limit برابر ۱ تا ۱۰۰ است. نبود paginated=1 مسیر سازگاری پاسخ آرایه‌ای قدیمی با سقف ۲۰۰ را نگه می‌دارد؛ رابط جدید از آن استفاده نمی‌کند. پارامترها: q، kind، transaction، status، area_min/max، price_min/max، deposit_min/max و rent_min/max. قیمت فروش به transaction=sale و ودیعه/اجاره به transaction=rent نیاز دارد. پاسخ صفحه‌بندی در OpenAPI ثبت شد؛ مصرف‌کننده برای دریافت آن باید paginated=1 بفرستد.

آزمون‌های تازه، تفکیک صفحات، شمارش پس از مجوز، مخفی‌ماندن پیش‌نویس دیگران، عدم نشت تماس، جداسازی دفتر و رد ورودی نامعتبر را پوشش می‌دهند. هر ۷۲ آزمون سرور با PostgreSQL و S3 واقعی، هم در محیط Python و هم داخل کانتینر موفق شد؛ TypeScript و build کانتینر موفق بود. فیلتر بدون نتیجه، فیلتر ترکیبی و ارقام فارسی در Chromium با عرض ۱۳۶۶ و ۳۹۰ موفق بودند. شواهد در evidence/inventory است. migration یا وابستگی جدیدی اضافه نشده است.

در حین ساخت، دیسک محیط پر شد؛ کش بلااستفاده Docker پاک شد و ۱۳ گیگابایت فضا آزاد شد. SeaweedFS پس از توقف نوشتن ناشی از کمبود فضا دوباره راه‌اندازی شد و اجرای مجدد هر ۷۲ آزمون موفق بود.

این تغییر تکمیل بخشی از مرحله ۱٫۱ است؛ تنظیمات کامل دفتر، بازنگری عرضه تأییدشده، ویترین/رضایت و مالی همچنان مرحله‌های بعدند. هیچ انتشار عمومی انجام نشده است.

اولین اقدام در محیط دارای Docker: دستورهای runbook، اجرای migration واقعی و تمام آزمون‌های core.tests، آزمون رسانه واقعی و سناریوی مرورگر با سه نشست جدا؛ هر شکست باید قبل از افزودن ماژول جدید رفع شود. سپس backup/restore و بررسی نشست/CSRF پشت HTTPS انجام شود. تا پیش از این مراحل، این نسخه آماده بهره‌برداری تجاری یا تأیید امنیتی نهایی محسوب نمی‌شود.

بعد از پذیرش: تنظیمات و فهرست‌های پایه، صفحه‌بندی/فیلتر، جزئیات فرم و بازنگری عرضه تأییدشده؛ سپس مشتری/تقاضا/تطبیق و همکاری. مالی و چنددفتره عملیاتی زودتر فعال نمی‌شوند.

برای ادامه در گفتگوی تازه، ابتدا README و این فایل و architecture-decisions.md خوانده شوند؛ وابستگی‌ها، داده‌ها و محدودیت‌های گزارش‌شده حفظ شوند. secrets،node_modules،.venv،buildها و نسخه‌های منبع در بسته سورس وجود ندارند.
