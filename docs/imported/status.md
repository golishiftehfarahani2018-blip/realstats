## اجرای بعدی در محیط دارای Docker

```bash
sh infra/verify.sh
```

این دستور باید در نصب آزمایشی جدا اجرا شود و آزمون‌های دو مرحله و S3 واقعی را اجرا می‌کند. پس از قبولی، سناریوی مرورگر در phase2.md، کنترل HTTPS/CSRF، backup/restore و اصلاح ایرادهای پیدا‌شده شرط پذیرش هستند. نسخه تا آن زمان آماده فروش یا بهره‌برداری نهایی نیست.

برای نصب تازه، بعد از seed_demo می‌توان seed_crm_demo را اجرا کرد؛ روی بانک دارای رکورد کاری متوقف می‌شود و چیزی را بازنویسی نمی‌کند. برای ارتقا، کلید رمزنگاری قبلی باید حفظ شود؛ migration اشخاص موجود آن را برای ساخت شاخص استفاده می‌کند.

فایل‌های کلیدی: backend/crm/services.py، people.py، matching.py، models.py، migrations/، tests.py و test_rules.py؛ رابط: frontend/app/crm-workspace.tsx. وابستگی جدید runtime اضافه نشده است.

محدودیت‌های آگاهانه: اسکن حداکثر ۱۰۰۰ عرضه در match؛ معیارهای پایه بدون امکانات/اتاق؛ ورود تاریخ میلادی با ساعت تهران و نمایش شمسی؛ نبود ادغام/اصلاح شماره شخص، یادآوری پس‌زمینه و پیامک. وضعیت جزئیات نسخه اول، مالی و ویترین در phase2.md و modules-and-stages.md ثبت شده است.

- مدیریت ایجاد و فعال/غیرفعال‌سازی مشاور توسط مدیر؛ نقش، دفتر و معرف از مرورگر پذیرفته نمی‌شود.

- پول صحیح تومان، مساحت Decimal، تاریخ آگاه از منطقه زمانی، نمایش شمسی/تهران و ارقام فارسی، یکسان‌سازی ورودی فارسی/عربی.
- کنترل نسخه و قفل ردیف، تاریخچه قیمت append-only، قیود ترکیبی دفتر/مجموعه، trigger منع تغییر معرف و هویت عرضه، ممیزی append-only.

- Dockerfile،Compose پایه/توسعه/تولید، Nginx هم‌مبدأ، migrationها، seed تصادفی و bootstrap تعاملی، قرارداد OpenAPI و مستندات ادامه پروژه.

## مانع محیطی دقیق

این محیط فقط UID صفر با یک شناسه نگاشت‌شده و بدون قابلیت تغییر کاربر دارد. باینری PostgreSQL دریافت شد، اما اجرای PostgreSQL با root مجاز نیست و محیط کاربر غیرroot قابل ایجاد/انتخاب نمی‌کند. Docker نیز وجود ندارد. اتصال 127.0.0.1:5432 با Connection refused متوقف شد. SQLite، سرویس ساختگی یا mock بانک جایگزین نشد. لاگ شکست در docs/evidence/database-test-blocker.txt است. نصب Chromium نیز با خطای فایل zip نامعتبر شکست خورد؛ هیچ آزمون تصویری یا مرورگری موفق ادعا نمی‌شود.

## شرط پذیرش مرحله اول و گام بعد

اولین اقدام در محیط دارای Docker: دستورهای runbook، اجرای migration واقعی و تمام آزمون‌های core.tests، آزمون رسانه واقعی و سناریوی مرورگر با سه نشست جدا؛ هر شکست باید قبل از افزودن ماژول جدید رفع شود. سپس backup/restore و بررسی نشست/CSRF پشت HTTPS انجام شود. تا پیش از این مراحل، این نسخه آماده بهره‌برداری تجاری یا تأیید امنیتی نهایی محسوب نمی‌شود.

بعد از پذیرش: تنظیمات و فهرست‌های پایه، صفحه‌بندی/فیلتر، جزئیات فرم و بازنگری عرضه تأییدشده؛ سپس مشتری/تقاضا/تطبیق و همکاری. مالی و چنددفتره عملیاتی زودتر فعال نمی‌شوند.

برای ادامه در گفتگوی تازه، ابتدا README و این فایل و architecture-decisions.md خوانده شوند؛ وابستگی‌ها، داده‌ها و محدودیت‌های گزارش‌شده حفظ شوند. secrets،node_modules،.venv،buildها و نسخه‌های منبع در بسته سورس وجود ندارند.
